# Demo.6 索引查询资源实验

## 方法

同一版本程序、同一临时 SQLite、同一问题、交替运行三次。600份合成文档，每份12块，共7200块；每块带128维零向量，向量只模拟数据体积，不参与语义判断。

- `indexed`：Server新路径，先元数据与FTS，读取当前页块正文，不加载向量。
- `generic_view`：通过测试包装器关闭 IndexedReader 能力，强制同一程序走原有通用 Snapshot/View 路径。
- 每轮都返回同样的3项。结果、范围和计数另有正确性测试。
- 记录 Go TotalAlloc 差额，不是峰值RSS；耗时不是HTTP往返时间。

## 当前环境的观测（各取三次中位数）

|路径|查询耗时|Go分配字节|约合MiB|
|---|---:|---:|---:|
|indexed|7.133 ms|2,410,288|2.30|
|generic_view|217.703 ms|98,154,456|93.61|

完整逐轮记录：`checks/demo6/load-probe.json`，日志：`load-probe.log`。三次不能代表广泛统计结果；这个实验说明当前实现避免了一部分整库正文/向量装载，不给出生产容量、吞吐、尾延迟或所有查询的速度承诺。

语义、图、+ask、direct没有被这个实验覆盖；词法相关性也没有通过资源实验验证。元数据、候选引用仍随数据规模增长，默认最多保存20,000项有序引用，并非恒定内存。

## 重跑

```bash
XRAG_LOAD_REPORT="$PWD/checks/demo6/load-probe.json" \
  go test ./tests -run '^TestDemo6ResourceProbe$' -count=1 -v
```

普通 `make test` 显式跳过本资源实验，以免每次单元测试都建立较大的合成资料；本轮已单独运行通过。重新运行的结果取决于机器，应使用新日志，而不是拿上述数字作为固定通过线。
