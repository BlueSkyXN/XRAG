    服务实际信息
    

    待启用配置
    只保存 env:/file: 引用，不在此输入真实密钥。引用由 Server 或 Worker 所在机器解析。保存成功不表示外部服务已经测试通过。
    

    当前进程实际配置
    

    创建访问 Key
    本 Demo 一把 Key 就是一个调用身份，不含独立的用户密码目录。
    新 Key 只在这里显示一次
    为不同应用创建独立 Key。更换 Key 可先创建、接入成功后再停用旧 Key。停用后，现有会话的下一次请求也会失效。
    系统不会停用最后一把永久管理员 Key，避免把所有管理入口关闭。
    

    导出当前知识库
    导出全部已发布 MD/TXT 及来源清单，不是当前搜索的前 K 项。不包含草稿、密钥或向量。
    Demo 上限：10,000 份文件、正文 64 MiB。它是内容导出，不是完整系统备份。
    数据库快照
    保存入库的正文、版本、草稿、反馈和 Key 摘要。外部来源目录、实际 Key 和外部数据库不在快照中。
    最多保留 20 个登记快照。大库备份会占用磁盘与查询连接，请在空闲时执行。
    

    恢复到一个新目录
    恢复必须在命令行显式执行，禁止通过网页覆盖运行中的库。新目录会生成恢复管理员 Key，并关闭原自动扫描与模型配置。
    ./bin/xrag-server restore --from snapshot.sqlite \
  --data /新的/不存在的目录 --confirm
    文档身份和旧引用保留；原 Key 停用、排队任务停止。外部来源路径重新确认后再启用。
    

    清理过期临时数据
    只清理已过期的结果页、范围句柄和查询摘要；不会删除知识、历史文件、模型缓存或任务。
    

    四步开始使用
    1. 在“资料与构建”上传 MD/TXT，或登记 Server 可读取的目录。
    2. 构建完成后，用“关键词”检索一个明确编号。
    3. 打开原文，确认内容和版本；需要时从结果提交反馈。
    4. 再配置语义或图后端，用同一组问题比较。
    把能力交给 Agent
    默认 MCP 是 tools 子集。使用指南随源码的 skills/xrag-retrieval/SKILL.md 提供；此处不声称所有客户端已经联调。
    

    配置保存后，为什么能力没变？
    当前进程继续使用启动时的配置。重启 Server 和所有 Worker 后再看“当前能力”；带 --config 启动时优先使用外部文件。改变向量模型后还需显式重建。
    任务一直排队怎么办？
    检查内置执行器是否关闭；按需单独运行 xrag-server worker --data 你的数据目录。关闭浏览器不会停止后台任务。
    为什么图里有关系，不代表已找到根因？
    当前默认图来自明确标注或配置的抽取器。路径只说明关联及其出处，不能代替因果分析。
    备份为什么不包含来源目录？
    数据库快照保留入库正文与历史。Git 工作区、未导入文件、Key 文件、环境变量和专业数据库由各自存储管理，需要单独备份。恢复后不要未确认来源就重新构建。
    统计 37 条，却只展示 10 条？
    总数是完整条件范围上的计算，10 条是当前页。读取下一页不会重新搜索。语义候选不提供整个知识库的精确总数。
